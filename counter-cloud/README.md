# 岐大祭 来場者カウンター（2ゲート・一般公開）

公開URLは https://counter.gidaisai.jp 。ログインなしで閲覧できます。
送信先は同じドメインの `/api/upload` で、32文字以上の専用Bearerトークンが必要です。
カメラ映像・接続情報は送信しません。公開ページのHTML・CSS・JavaScriptは `worker/public/` に分け、API処理は `worker/src/` に置いています。

## 集計の仕組み

- `gate-1` と `gate-2` が、日本時間の当日の累計入場・退場人数を10秒ごとに送信します。
- D1は日付とゲートごとに最新の累計を保存します。再送は加算せず、新しい時刻の値だけで上書きします。
- Webは当日分だけを合算します。片方が未着なら受信済みゲートだけの参考値、停止中なら最後の受信値を含む参考値と明記します。
- 受信から30秒を超えると通信停止、最終映像処理から15秒を超えると映像処理遅延と表示します。
- 各ゲートの入場−退場は、そのゲートだけの滞在人数ではありません。2ゲートの差を合算した値を全体の推定滞在人数として表示します。
- PC再起動時も同じゲートIDと同じローカルDBを使ってください。2つの送信元に同じゲートIDを割り当てないでください。
- 日次集計なので日付をまたぐ滞在人数は引き継ぎません。推移グラフ、過去日の補完送信は未実装です。

## Cloudflareの公開準備

`worker/` で実行します。既存環境は `npm ci` で依存関係を準備してください。

1. `npx wrangler login` で対象アカウントにログイン。
2. `gidaisai.jp` がそのアカウントで管理されているか確認。
3. `wrangler.jsonc` のD1データベースが対象アカウントに存在するか確認。
4. `counter.gidaisai.jp` にCloudflare Accessの閲覧制限が設定されていないか確認。
5. 送信用の専用ランダムトークンを用意し、`npx wrangler secret put UPLOAD_TOKEN` で登録。
6. `npx wrangler d1 migrations apply gidaisai-counter --remote` でテーブルを追加。
7. `npm test` の後、`npx wrangler deploy` で公開。

`0002.sql` は既存の1台用テーブルを残し、2ゲート用テーブルを新設します。
古いデータはゲートを特定できないため、自動では合算しません。各送信元から届いた当日累計を使用します。

## 起動方法

`visitor_counter.py` に `--gate-id gate-1` または `--gate-id gate-2` を指定すると、送信プログラムがバックグラウンドで自動起動し、計測終了時に一緒に停止します。カメラ1台につきターミナル1つで動かせます。

完成形コマンドは[ルートREADMEの2ゲート運用](../README.md#2ゲート運用の起動コマンド)を参照してください。送信専用トークンは起動時に非表示で入力します。PCの時計は自動同期を有効にしてください。

`upload_counts.py` は送信部分の小さなプログラムとして残り、計測側から自動で呼び出されます。必要な場合は、計測と切り離して個別に起動することもできます。

## 実機での確認

1. ログインなしでページを開ける。
2. ゲート別の人数が各計測プログラムと一致し、全体がその合計になっている。
3. 同じ累計を繰り返し送信しても人数が増えない。
4. 片方の送信を止め、30秒超でそのゲートの停止と合計の参考値表示が出る。
5. 再開すると最新累計で復旧し、二重加算しない。
6. カメラ処理を止めると、そのゲートの映像処理遅延が出る。
7. 翌日は前日分が合計に混ざらない。
